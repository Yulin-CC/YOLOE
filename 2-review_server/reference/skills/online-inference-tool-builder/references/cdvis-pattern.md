# CDVIS 模式提炼

此 Skill 来源于 `cdvis` 变化检测在线推理项目。这里记录可复用事实与应升级的边界，供要求“像 CDVIS 一样”时读取。

## 项目形态

- Python 3.8+ 标准库服务：`ThreadingHTTPServer` 同时提供静态文件、JSON API 和任务图片。
- 原生 HTML/CSS/JavaScript 前端，无构建步骤、无第三方运行依赖。
- `config.json` 提供模型后端、监听地址/端口、超时和最大请求体；命令行可覆盖主要配置。
- `server.py` 是最小启动入口，核心逻辑集中在 `app.py`。

这一形态非常适合可信局域网里的可复制工具。它不是默认的互联网生产架构。

## 端到端链路

1. 页面读取安全配置与历史任务。
2. 用户选择模型、参数以及单组 A/B 图或两个文件夹。
3. 文件夹按相对路径同名或末尾 `_a/_b` 规则配对。
4. 页面创建任务，再逐组把 A/B 图片转 Data URL 提交。
5. 服务端立即保存原图，分别上传到算法服务，再调用变化检测接口。
6. 每组完成后将状态、耗时、错误、区域和原始响应原子写入 `task.json`。
7. 页面调用 finish 汇总为完成、部分失败或失败；历史页可重新打开结果。

这个“三段式任务 API + 逐项落盘”是最核心的可复用模式。它使小批量任务具有可观察进度和部分结果保留能力。

## 数据与 API

任务目录：

```text
data/<task-id>/
  task.json
  files/
    0001_A.jpg
    0001_B.jpg
```

核心路由包括读取配置、任务列表、任务详情、创建任务、提交图片组、结束任务和删除任务。列表返回摘要，详情返回 `pairs`。每个 pair 保存 `status`、本地图像 URL、`regions`、后端原始响应、错误和毫秒耗时。

服务端使用严格任务 ID 正则、解析后路径边界检查、请求体上限、图片扩展名白名单、同目录临时文件 + `os.replace`，删除时拒绝符号链接。这些是轻量文件存储中应保留的防线。

## 结果查看器

- 双 Canvas 并排显示 A/B 图。
- 使用共享的归一化中心、缩放和指针，支持同步缩放/平移。
- 模型输出为 `[0,1]` 归一化多边形点；同一变化区域叠加到两幅已配准图。
- 支持颜色、透明度、显隐、复位、区域数、耗时、失败信息和图片组导航。
- Canvas 根据 device pixel ratio 调整实际像素，并在容器 resize 后重绘。

## 值得保留的工程决策

- 工具后端代理模型服务，浏览器不直接跨域调用算法接口。
- 任务与逐项状态都持久化，失败不会抹掉已成功项。
- 原图保存在任务目录，历史结果不依赖算法服务临时 URL。
- UI 对动态文本做 HTML 转义，API 包装器统一处理错误。
- 批量按顺序处理，适合保护单实例模型服务。

## 后续项目应主动评估的限制

- 浏览器负责批量编排：页面关闭会停止剩余提交，重启后 `running` 任务不会自动继续。
- Base64 JSON 使内存和请求体膨胀，不适合超大图片或大批量。
- 单进程锁只保护当前 Python 进程；多个服务进程共享 JSON 目录会发生竞争。
- 页面允许覆盖任意后端 URL，在不可信网络中会形成 SSRF 风险。
- 只按扩展名验图，没有文件签名/实际解码校验。
- 没有认证、任务所有权、存储配额、取消、服务端队列或自动清理。
- 模型编号和字段散落在前后端，模型继续增加时应改成注册表与 adapter。

后续 AI 应根据部署和规模决定保留轻量性还是升级这些限制，而不是机械复刻。

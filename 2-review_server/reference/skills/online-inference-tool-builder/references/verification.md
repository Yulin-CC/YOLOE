# 验证与交付

## 分层验证

### 纯逻辑

优先测试容易出错且不依赖网络的函数：

- 文件过滤、规范化键、配对、重复与缺失检测。
- 参数边界、任务状态汇总、结果坐标转换。
- 任务 ID 与安全路径解析。
- adapter 对成功/失败样例的响应规范化。

### 后端 API

使用临时数据目录，避免污染真实历史。覆盖：

- 启动与 `/api/config`。
- 创建任务、读取列表/详情、逐项成功和逐项失败、终结状态。
- 非法 JSON、超大请求、非法任务 ID、不存在任务。
- 删除只能作用于合法任务目录。
- 写入中断或损坏 `task.json` 时的可解释行为。

若真实模型服务不可用，启动一个本地 mock，模拟成功、业务错误、HTTP 错误、非 JSON 和超时。mock 验证的是协议与错误处理，不等于真实联调。

### 浏览器

至少手工或自动验证：

1. 单组输入完整提交并展示结果。
2. 批量配对、未配对提示、进度变化和部分失败。
3. 刷新页面后历史仍在，打开任务恢复原图与结果。
4. 删除确认、删除后列表与当前视图一致。
5. 查看器缩放、拖拽、显隐、复位和切换输入项。
6. 空状态、无区域、加载失败和长错误文案不破坏布局。

## 必测失败矩阵

| 阶段 | 场景 | 期望 |
|---|---|---|
| 输入 | 空文件/不支持类型/重复配对键 | 提交前明确阻止或列出 |
| 上传 | A 成功、B 失败 | 当前项失败，指出 B 上传阶段 |
| 推理 | 超时/业务码失败/非 JSON | 错误可见，任务可继续处理其他项 |
| 输出 | 坐标缺失/NaN/越界 | 协议错误或按已声明策略处理 |
| 持久化 | 刷新/重启/损坏记录 | 已完成结果可恢复，异常记录可诊断 |
| 删除 | 路径穿越/符号链接 | 服务端拒绝 |

## 规模与性能检查

记录测试文件大小、项数、模型耗时和浏览器内存。浏览器 Base64 会额外占用内存和约三分之一传输体积；当批量量级使页面明显卡顿时，改用流式 multipart、服务端上传与队列，而不是继续提高请求体上限。

检查任务列表是否只返回摘要；大原图和大型原始响应不应嵌入列表。为历史存储提供容量边界或清理策略，但未经用户授权不要自动删除已有任务。

## 交付说明模板

交付信息应简短包含：

- 入口：启动命令与访问地址。
- 配置：模型后端、鉴权、超时、大小/并发限制的设置位置。
- 数据：任务与原图保存位置、删除/保留行为。
- 验证：真实模型联调或 mock 验证分别覆盖了什么。
- 边界：当前实现适合的用户数、批量规模和已知限制。

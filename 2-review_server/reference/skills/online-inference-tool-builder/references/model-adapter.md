# 模型服务 Adapter

## 目标

让任务、持久化和 UI 只依赖稳定的领域结果，不依赖某个算法服务的上传接口、业务码或字段名。每种模型协议由 adapter 完成四件事：校验参数、准备输入、调用推理、规范化输出。

概念接口：

```python
class ModelAdapter:
    def validate_params(self, params): ...
    def infer(self, inputs, params, context): ...
    def normalize(self, response, input_meta): ...
```

小项目不必真的创建抽象基类，但相关代码应集中，路由层只调用一个清晰入口。

## 对接清单

从真实文档或样例响应确认：

- 基础 URL、推理路径、HTTP 方法和鉴权位置。
- 输入是 multipart、Base64、可访问 URL，还是先上传再提交 URL。
- 文件字段、角色顺序、模型 ID、参数名、单位、默认值和边界。
- HTTP 成功与业务成功分别如何判断。
- 成功、空结果、业务错误、非 JSON、超时的真实响应样例。
- 输出坐标是像素还是归一化，基于原图还是预处理尺寸，点序和掩膜编码。
- 是否幂等、是否支持请求 ID、取消、批量调用和并发上限。

不要只依据一次成功响应完成 adapter；至少保留一个成功与一个失败契约样例用于测试。

## 常见调用模式

### 先上传再推理

1. 后端接收浏览器文件并先保存本地原图。
2. adapter 分别上传输入，验证每次响应并取得 URL/资源 ID。
3. adapter 用这些引用调用推理端点。
4. 将供应商结果转换成领域结果；按配置决定是否保存原始响应。

任一上传失败时，该项失败且记录具体阶段。若供应商支持删除临时资源，可在明确授权与安全条件下清理；不要把清理失败覆盖为推理失败。

### 单次 multipart / Base64

仍由工具后端代理，避免浏览器处理服务密钥和跨域差异。Base64 会增加请求体体积，限制应按编码后大小估算；大文件优先流式 multipart 或对象存储。

## 超时、重试与错误

- 分开设置连接超时与总读取/推理超时（框架支持时）。
- GET/状态查询可做有限退避重试；昂贵推理 POST 只有在幂等键或协议明确保证时才重试。
- 向 UI 返回稳定、可行动的信息，例如“上传 A 图失败”“模型服务 180 秒未返回”；详细异常与诊断 ID 留在服务端日志。
- 供应商返回 HTTP 200 但业务码失败时，仍视为失败。
- 非 JSON、结构缺字段或坐标非法时作为协议错误，不用空结果掩盖。

## 输出规范化

推荐统一为带类型的结果：

```json
{"type":"classification","labels":[{"name":"cat","score":0.93}]}
{"type":"boxes","regions":[{"label":"car","score":0.88,"box":{"x":0.1,"y":0.2,"w":0.3,"h":0.2}}]}
{"type":"polygons","regions":[{"label":"change","points":[{"x":0.1,"y":0.2}]}]}
{"type":"text","text":"...","fields":{}}
```

若供应商返回像素坐标，用明确的参考宽高转换；超出范围的值按协议决定拒绝或裁剪，并记录诊断。不要在 renderer 中散落供应商字段解析。

## 可配置模型注册表

有多个模型时，用注册表声明 `id`、展示名、输入角色、参数 schema、adapter 和 renderer。前后端都应由同一份或可校验的配置生成选择项，避免 HTML、JavaScript、路由和 adapter 四处硬编码模型编号。

共享部署时，后端地址只能来自服务端注册表/环境配置。允许页面临时填写任意 URL 仅适用于可信本地环境，并应在文档中明确风险。
